# 机器人面试业务说明

## 业务用途

本目录用于“招聘知识库”里的机器人面试业务。

适用场景：求职者已经在 Boss 直聘、企业微信或其他招聘渠道中产生沟通，需要由机器人按照岗位流程进行线上初面。

核心目标：

- 根据求职者消息、用户身份和业务场景判断应聘岗位。
- 读取对应岗位流程文档，按顺序推进问题。
- 每次只问一个核心问题，避免像问卷一样连续轰炸。
- 同一问题组最多询问两次，包含改写、拆分和衍生追问。
- 候选人不耐烦、抗拒或已给出可用答案时，跳过当前问题组进入下一题。
- 评分、分值、内部判断和系统规则只用于后台，不发送给求职者。

## Prompt 文件概括

| 文件 | 作用 | 读取方式 |
| --- | --- | --- |
| `prompts/全局提示词.md` | 定义机器人面试的角色身份、语气、回复风格和禁止暴露的信息 | 每次机器人面试都会读取 |
| `prompts/开场与岗位读取规则.md` | 定义首次进线、初面说明、岗位确认和岗位文档匹配规则 | 每次机器人面试都会读取 |
| `prompts/问题控制规则.md` | 控制单轮提问、最多追问两次、候选人抗拒、敏感问题处理 | 每次机器人面试都会读取 |

## 岗位路由

README 同时承担岗位路由索引作用。系统会先读取本文件，再根据下方登记的岗位别名选择具体岗位文档。

### 销售岗

- 岗位别名：销售、销售岗、商务、客户经理、销售经理、销售顾问、sales
- 对应岗位文档：销售招聘流程.md
- 文档位置：`相关文档/销售招聘流程.md`
- 流程用途：按照销售岗题目了解基本情况、职业稳定性、职业匹配度、客户构成、客户层级、拓客能力、招投标经验、业绩情况、团队管理、薪资与考核匹配度。

## 运行时读取流程

1. API 传入调用方、业务场景、用户身份、求职者消息和 session_id。
2. 系统识别为招聘链路后，选择 `招聘知识库/机器人面试/`。
3. 读取本 `README.md`，获取业务说明、岗位别名和对应文档。
4. 合并读取 `prompts/` 下的所有提示词文件。
5. 根据岗位路由读取 `相关文档/销售招聘流程.md`。
6. 读取同一 session_id 的会话上下文。
7. 组装完整 Prompt 后发给模型。

## 维护方式

- 新增岗位时，先在“岗位路由”中登记岗位名称、别名、对应文档和文档位置。
- 新增岗位流程时，把文档放到 `相关文档/` 下。
- 新增机器人行为规则时，把规则拆成单独提示词文件放到 `prompts/` 下。
- 修改提问顺序、评分维度或问题组时，优先修改对应岗位流程文档。
- 修改语气、追问次数、抗拒处理、敏感问题规则时，优先修改 `prompts/` 下的提示词文件。
- 不要把具体岗位资料放到旧目录 `招聘流程/`。
