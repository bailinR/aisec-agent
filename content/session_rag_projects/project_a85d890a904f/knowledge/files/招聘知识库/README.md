# 招聘知识库

## 知识库用途

本知识库用于招聘相关的自动回复场景，包括 Boss 直聘沟通、求职者私信承接、机器人初面、岗位流程匹配、候选人问题处理和招聘合规话术。

API 调用时通常会传入：

- 调用方：例如 Boss 直聘、企业微信、OpenClaw。
- 业务场景：例如机器人面试、Boss 沟通、岗位咨询。
- 用户身份：例如求职者姓名、应聘岗位、经验、来源账号。
- 求职者消息：本轮需要回复的内容。
- session_id：用于读取同一候选人的历史上下文。

系统会根据这些信息选择对应业务目录，再读取该业务目录下的 README、提示词和相关文档，组装最终发给 AI 的 Prompt。

## 推荐目录规范

每个业务目录建议保持如下结构：

```text
业务名称/
  README.md          # 业务说明、文件清单、读取规则、岗位或场景路由
  prompts/           # 该业务专属提示词，可拆分多个文件
  相关文档/          # 具体岗位、流程、话术、合规或业务资料
```

## Prompt 组装方式

招聘回复接口的核心组装顺序：

1. 根据调用方、业务场景、用户身份、求职者消息判断是否进入招聘链路。
2. 在 `招聘知识库/` 下选择最匹配的业务目录。
3. 读取业务目录的 `README.md`，用于了解该业务有哪些岗位、场景、文件和匹配规则。
4. 合并读取 `prompts/*.md`，作为该业务的提示词规则。
5. 根据 README 中的岗位或场景映射，读取 `相关文档/` 中的具体资料。
6. 叠加同一 `session_id` 的会话上下文。
7. 组装完整 Prompt 后调用模型生成回复。

## 维护规则

- 新增业务时，先创建业务目录和 `README.md`。
- 新增提示词时，放到该业务目录的 `prompts/` 下，并在 README 中写明作用。
- 新增具体资料时，放到该业务目录的 `相关文档/` 下，并在 README 中登记文件用途和触发条件。
- 不要把具体岗位流程放回旧目录 `招聘知识库/招聘流程/`。
- 不要把业务提示词放回旧目录 `招聘知识库/prompts/`。
- 如果删除了某个文件，不要通过默认模板重新生成同名旧文件。
