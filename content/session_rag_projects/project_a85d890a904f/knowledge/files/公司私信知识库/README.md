# 公司私信知识库

## 知识库用途

本知识库用于短视频评论承接、首次私信、私信维护、评论区维护、活动承接和客户意向识别。

API 调用时通常会传入：

- 调用方：例如抖音、视频号、小红书、OpenClaw 或内部测试页面。
- 业务场景：例如评论转私信、首次私信、私信维护、评论区维护。
- 用户评论：本轮需要回复或承接的评论内容。
- 视频概述：评论所在视频大概讲了什么方向。
- 用户身份或目标：例如当前账号身份、希望引导到微信号、企业微信、预约入口或资料页。
- session_id：用于读取同一用户的历史上下文。

系统会根据这些信息选择对应业务目录，再读取该业务目录下的 README、提示词和相关文档，组装最终发给 AI 的 Prompt。

## 推荐目录规范

每个业务目录建议保持如下结构：

```text
业务名称/
  README.md          # 业务说明、文件清单、读取规则、场景或产品路由
  prompts/           # 该业务专属提示词，可拆分多个文件
  相关文档/          # 具体产品、服务、活动、合规或样本资料
```

## Prompt 组装方式

公司私信回复接口的核心组装顺序：

1. 根据调用方、业务场景、视频概述、用户评论判断是否进入公司私信链路。
2. 在 `公司私信知识库/` 下选择最匹配的业务目录。
3. 读取业务目录的 `README.md`，用于了解该业务有哪些场景、文件和匹配规则。
4. 合并读取 `prompts/*.md`，作为该业务的提示词规则。
5. 根据 README 中的场景或产品映射，读取 `相关文档/` 中的具体资料。
6. 叠加同一 `session_id` 的会话上下文、活动设置、人员身份和用户目标。
7. 组装完整 Prompt 后调用模型生成回复。

## 维护规则

- 新增业务时，先创建业务目录和 `README.md`。
- 新增提示词时，放到该业务目录的 `prompts/` 下，并在 README 中写明作用。
- 新增具体资料时，放到该业务目录的 `相关文档/` 下，并在 README 中登记文件用途和触发条件。
- 公司定位、三大业务板块、产品资料、活动规则、合规边界要分开存放。
- 不要把提示词混进产品资料文档。
- 不要把医疗效果、价格、名额、平台规则写成确定承诺，除非业务资料明确提供。
- 如果删除了某个文件，不要通过默认模板重新生成同名旧文件。
