# 评论转私信业务说明

## 业务用途

本目录用于“公司私信知识库”里的评论转私信业务。

适用场景：用户在短视频评论区留言后，需要根据视频概述、评论内容、项目资料、活动设置和会话上下文生成首次私信或后续私信回复。

核心目标：

- 识别评论对应的业务方向和用户意向强弱。
- 读取最相关的业务资料，而不是一次塞入所有资料。
- 根据不同业务方向选择合适人员身份。
- 首次私信要承接用户评论，让用户愿意继续回复。
- 后续私信要围绕用户问题推进，不重复制造关键词领取。
- 活动、资料包、评估、体验入口只作为自然承接，不夸大承诺。

## 运行时读取流程

1. API 传入调用方、业务场景、视频概述、用户评论、用户目标和 session_id。
2. 系统识别为公司私信链路后，选择 `公司私信知识库/评论转私信/`。
3. 读取本 `README.md`，获取业务说明、业务别名、对应资料和身份建议。
4. 合并读取 `prompts/` 下的所有提示词文件。
5. 根据视频概述和用户评论读取最相关的 `相关文档/`。
6. 读取同一 session_id 的会话上下文、活动设置和页面/API 入参中的目标。
7. 组装完整 Prompt 后发给模型。

## 维护方式

- 新增产品时，先在“场景路由”中登记业务名称、别名、建议身份、对应资料和必读边界。
- 新增业务资料时，把文档放到 `相关文档/` 下。
- 新增回复行为规则时，把规则拆成单独提示词文件放到 `prompts/` 下。
- 修改公司事实、产品能力、合规要求时，优先修改 `相关文档/`。
- 修改语气、首次私信结构、活动表达、上下文读取方式时，优先修改 `prompts/`。
