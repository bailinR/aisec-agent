# 数据中台调用：账号活性与蓝V检测

本文给 **comment-kit（数据中台）** 使用。私信系统提供统一验号接口：先检测 Cookie 能否登录（账号活性），仅在活性通过后再检测账号类型（蓝 V / 普通号）。失活时跳过类型检测。

测试地址：`http://127.0.0.1:7860`  
生产环境替换为实际私信 Web 地址（与 `private_message_provider.send_base_url` 相同）。

---

## 1. 接口

```http
POST /api/v1/douyin/private-message/accounts/verify
Content-Type: application/json
```

兼容路径（可选）：`/api/douyin/private-message/accounts/verify`

---

## 2. 请求字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `account_cookie` / `account_cookies` / `cookie` / `cookies` | **是** | 发送账号 Cookie；支持 `name=value; ...` 或 `{"cookies":[...]}` |
| `browser_name` / `browser` | 否 | 默认 `chrome`；也可用 `edge` |
| `headless` | 否 | 默认 `true`（服务端无头检测） |
| `open_url` | 否 | 默认 `https://www.douyin.com/` |
| `timeout_ms` | 否 | 默认 `45000` |
| `keep_browser_open` | 否 | 默认 `false`；联调扫码时可设 `true` |

请求示例：

```json
{
  "account_cookie": "sessionid=xxx; sid_guard=xxx",
  "browser_name": "chrome",
  "headless": true
}
```

PowerShell 示例：

```powershell
$body = @{
  account_cookie = "sessionid=xxx; sid_guard=xxx"
  browser_name = "chrome"
  headless = $true
} | ConvertTo-Json -Compress

Invoke-RestMethod `
  -Uri "http://127.0.0.1:7860/api/v1/douyin/private-message/accounts/verify" `
  -Method POST `
  -Body $body `
  -ContentType "application/json; charset=utf-8"
```

---

## 3. 响应结构

外层统一信封：

```json
{
  "code": 0,
  "msg": "success",
  "data": { ... }
}
```

`data` 重点字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| `cookie_valid` | bool | Cookie 是否可登录（活性是否通过） |
| `activity_status` | string | `active` / `expired` / `risk` / `error` / `unknown` |
| `activity_reason` | string | 活性说明，可供展示 |
| `account_type` | string | `blue_v` / `personal` / `unknown` |
| `account_type_label` | string | `蓝V账号` / `普通账号` / `未识别` |
| `account_type_reason` | string | 类型判定原因；失活时为「活性验证失败，未执行账号类型检测」 |
| `is_blue_v` | bool | 是否蓝 V |
| `account_type_skipped` | bool | 是否因失活跳过了类型检测 |
| `nickname` | string | 识别到的昵称（可能为空） |
| `douyin_unique_id` | string | 抖音号（可能为空） |
| `uid` / `sec_uid` | string | 可选身份字段 |
| `requires_login` | bool | 是否判定为需要重新登录 |
| `requires_verification` | bool | 是否需要二次/安全验证 |

### 3.1 活性通过 + 蓝 V

```json
{
  "code": 0,
  "msg": "success",
  "data": {
    "cookie_valid": true,
    "activity_status": "active",
    "activity_reason": "Cookie 可登录",
    "account_type": "blue_v",
    "account_type_label": "蓝V账号",
    "account_type_reason": "enterprise_verify_reason",
    "is_blue_v": true,
    "account_type_skipped": false,
    "nickname": "某品牌官方",
    "douyin_unique_id": "brand_01"
  }
}
```

### 3.2 活性通过 + 普通号

```json
{
  "data": {
    "cookie_valid": true,
    "activity_status": "active",
    "account_type": "personal",
    "account_type_label": "普通账号",
    "is_blue_v": false,
    "account_type_skipped": false
  }
}
```

### 3.3 Cookie 失活（跳过类型检测）

```json
{
  "data": {
    "cookie_valid": false,
    "activity_status": "expired",
    "activity_reason": "需要重新登录（Cookie 失活或未登录）",
    "account_type": "unknown",
    "account_type_label": "未识别",
    "account_type_reason": "活性验证失败，未执行账号类型检测",
    "is_blue_v": false,
    "account_type_skipped": true,
    "requires_login": true
  }
}
```

---

## 4. 中台建议处理

| 条件 | 建议 |
|---|---|
| `cookie_valid=true` 且 `account_type=blue_v/personal` | 更新账号活性为可用，并保存账号类型 |
| `activity_status=expired` / `cookie_valid=false` | 标记账号失活，提示更新 Cookie；**不要**用旧的蓝 V 结论覆盖 |
| `activity_status=risk` | 需人工处理二次验证；中台应提供 **有头验证** 入口，见 `docs/数据中台对接账号验活-人工验证有头模式.md` |
| `activity_status=error` | 看 `failure_summary` / `activity_reason`，可重试 |

伪代码：

```text
resp = POST /accounts/verify { account_cookie, browser_name }
d = resp.data
save activity_status, activity_reason, cookie_valid
if d.cookie_valid and not d.account_type_skipped:
    save account_type, is_blue_v, nickname, douyin_unique_id
else:
    # 不更新账号类型，或置为 unknown
    keep previous account_type OR set unknown
```

---

## 5. 与旧接口关系

| 接口 | 用途 |
|---|---|
| `POST .../accounts/verify`（本接口） | **中台推荐**：活性 + 类型，失活跳过类型 |
| `POST .../account-cookie/apply` | 本地调试「应用 Cookie / 测试账号类型」，可能有头保留浏览器 |

发送任务、回复检测仍用原有 tasks / conversations/read 接口。

---

## 6. 安全

- 请求中的 Cookie 为敏感凭证，勿写入普通业务日志。
- 响应不回显 Cookie 原文。
- 建议 HTTPS + 服务间鉴权（与现有私信任务接口一致）。

---

## 7. 联调检查

1. 私信 Web 已启动（7860）  
2. 用有效 Cookie 调用 → `activity_status=active`，并得到 `blue_v` 或 `personal`  
3. 用失效 Cookie 调用 → `expired`，且 `account_type_skipped=true`、`account_type=unknown`  
4. 中台账号管理「检测」按钮改为调本接口并落库上述字段  
5. `activity_status=risk` 时中台提供「打开浏览器验证」（有头第二段），见 `docs/数据中台对接账号验活-人工验证有头模式.md`
