# 浏览器异常人工接管

日期：2026-07-16

这份文档说明服务器无头浏览器遇到登录、风控、二次验证时，如何设计人工接管流程。

## 1. 基本结论

服务器无头模式启动的浏览器，默认看不到图形界面。

如果要直接看到服务器上的有头浏览器，通常需要：

- 远程桌面。
- VNC。
- X11 转发。
- 其他远程可视化方案。

但更推荐的业务形态是：

```text
服务器：接收任务、排队、生成内容、记录状态、自动执行正常任务
人工机：只在异常时打开浏览器，处理扫码、登录、二次验证、风控确认
服务器：异常恢复后继续无头执行后续任务
```

## 2. 什么是唯一执行点

“唯一执行点”不是说所有浏览器都必须只跑在服务器上，而是说任务状态和自动执行权必须只有一个主控。

在当前方案里：

- 服务器是任务主控。
- Redis 是队列和任务状态来源。
- worker 是自动任务执行者。
- 人工机只处理异常恢复，不长期抢任务。

这样可以避免：

- 同一个账号被两台机器同时操作。
- 同一个目标用户重复私信。
- 人工机和服务器状态不一致。
- 任务失败后不知道该以谁的结果为准。

## 3. 推荐流程

### 正常任务

```text
上游系统 -> Web API -> Redis 队列 -> worker -> Playwright 无头执行 -> 写回结果
```

### 异常任务

```text
worker 检测到登录/验证/风控
  -> 任务状态写为 manual_required
  -> 写入 failure_code、failure_stage、failure_summary、failure_screenshot_url
  -> 人工机读取需要处理的任务
  -> 人工机打开有头浏览器处理登录、扫码或二次验证
  -> 同步新的 Cookie/登录态/恢复结果
  -> 服务器任务回到待执行或重试队列
  -> worker 继续无头执行
```

## 4. 人工机应该负责什么

人工机只负责异常恢复：

- 打开有头浏览器。
- 扫码登录。
- 处理二次验证。
- 处理账号风控提示。
- 更新 Cookie 或浏览器登录态。
- 标记任务可重试。

人工机不建议长期负责：

- 批量任务排队。
- 私信内容生成。
- 批量发送。
- 状态主记录。
- 重试和死信管理。

这些仍应由服务器完成。

## 5. 什么情况进入人工接管

常见触发条件：

- `login_required`：登录态失效。
- `verification_required`：需要二次验证。
- `account_risk`：账号风控或发送限制。
- `cookie_invalid`：Cookie 无效或过期。
- `rate_limited`：验证码或限流。
- `message_send_unconfirmed`：点击后无法确认发送成功。
- 页面出现扫码、滑块、短信验证、账号安全提示。

任务查询时重点看：

- `status`
- `manual_required`
- `failure_code`
- `failure_stage`
- `failure_summary`
- `failure_screenshot_url`
- `failure_screenshot_exists`

## 6. 人工接管后的状态回流

人工处理完成后，必须把结果回写给服务器。

建议至少记录：

- 任务 ID。
- 账号标识。
- 处理人。
- 处理时间。
- 处理动作：扫码、短信验证、重新登录、确认风险提示。
- 新 Cookie 或会话状态是否可用。
- 是否允许重试。

状态建议：

- `manual_required`：等待人工。
- `manual_processing`：人工处理中。
- `manual_resolved`：人工处理完成，可重试。
- `retry_wait`：等待 worker 重试。
- `dead_letter`：人工确认不可恢复。

## 7. 为什么不建议让上游电脑长期跑全部浏览器

可以让上游电脑打开浏览器处理异常，但不建议让它变成完整执行端。

原因：

- 上游电脑关机、断网、休眠会中断任务。
- 多人多机器容易重复发送。
- 任务日志、截图、失败原因分散。
- 不利于排队、重试、限流和审计。

更稳的做法是：

- 服务器负责稳定执行和记录。
- 人工机作为异常恢复工具。
- 每个账号同一时间只允许一个执行者操作。

## 8. 和日志排查的关系

人工接管不是替代日志。

排查顺序：

1. 先查任务详情接口，看 `failure_code` 和 `failure_summary`。
2. 再看失败截图。
3. 再看 worker 日志。
4. 判断是否需要人工接管。
