# 常用接口文档

日期：2026-07-16

## 1. 基础地址

- 本地：`http://127.0.0.1:7860`
- 局域网：`http://192.168.1.70:7860`，以当前机器实际局域网 IP 为准
- 服务器：`http://8.217.122.152:8091`

说明：
- 本地和服务器通常共用同一套路径。
- 区别只在 base URL。
- 服务器当前通过 Nginx 暴露 `8091`，代理到容器里的 `7860`。
- `127.0.0.1` 只能在服务所在机器上访问。
- 局域网访问必须让 Web 服务监听 `0.0.0.0:7860`，否则 `http://192.168.x.x:7860` 会访问失败。
- 判断是否已经监听局域网：`Get-NetTCPConnection -LocalPort 7860 -State Listen`，看到 `0.0.0.0:7860` 才表示已映射到局域网。

## 2. 健康检查

### `GET /api/health`

用途：检查服务是否正常启动。

示例：
```bash
curl http://8.217.122.152:8091/api/health
```

返回示例：
```json
{"code":0,"msg":"success","data":null}
```

## 3. 任务相关

### `POST /api/v1/douyin/private-message/tasks`

用途：提交私信任务。

外部系统常用地址：

```http
POST http://192.168.1.70:7860/api/v1/douyin/private-message/tasks
```

服务器地址：

```http
POST http://8.217.122.152:8091/api/v1/douyin/private-message/tasks
```

请求体示例：
```json
{
  "task_id": "postman_dm_test_011",
  "video_info": "视频讲膝盖疼、上下楼疼、骨积液和干细胞评估方向。",
  "account_cookie": "sessionid=xxx; sid_guard=xxx",
  "comment_info": "我二舅膝盖上下楼疼，这个适合吗",
  "message": "您好，看到您刚才的留言了。我先把相关资料发您看看。",
  "target_profile_url": "https://www.douyin.com/user/xxxx",
  "project_name": "大健康AI跨境综合企业服务平台"
}
```

`message` 是可选的私信内容字段。非空时跳过 AI 生成，直接发送该内容，此时 `video_info`、`comment_info`、`project_name` 可以省略；未传或为空时，按原流程先生成再发送。

说明：
- 普通外部调用不需要传 `debug_mode`。
- 当前默认会强制 `run_mode=send`、`auto_send=true`、`auto_process=true`，并默认采用有头模式。
- 提交接口是异步接口，`accepted: 1` 只代表入队成功，不代表已经发出。
- 真正是否发出要查任务详情，看 `status=success`、`sent=true`、`queue_status=done`。

### `GET /api/v1/douyin/private-message/tasks`

用途：查看任务列表、队列状态。

常用参数：
- `limit`：返回条数，默认 `20`

示例：
```bash
curl "http://8.217.122.152:8091/api/v1/douyin/private-message/tasks?limit=20"
```

局域网示例：

```bash
curl "http://192.168.1.70:7860/api/v1/douyin/private-message/tasks?limit=20"
```

### `GET /api/v1/douyin/private-message/tasks/{task_id}`

用途：查看指定任务的详细状态、失败原因、截图信息。

示例：
```bash
curl "http://8.217.122.152:8091/api/v1/douyin/private-message/tasks/postman_dm_test_011"
```

判断发送成功时重点看：

```json
{
  "status": "success",
  "queue_status": "done",
  "sent": true
}
```

如果是 `pending / queued`，代表任务已入队但 worker 还没执行；如果长期不动，先检查 worker 是否启动。

### `POST /api/v1/douyin/private-message/tasks/clear`

用途：清空当前 Redis 里的私信任务数据和队列。

示例：
```bash
curl -X POST "http://8.217.122.152:8091/api/v1/douyin/private-message/tasks/clear"
```

## 4. 模型 Key 相关

### `POST /api/v1/model/config/save`

用途：保存模型配置，包含 `api_key`。

说明：
- 这是“服务器-key”常用接口。
- 若不传 `api_key`，通常会沿用已有配置。

### `GET /api/v1/model/configs`

用途：查看当前已保存的模型配置。

说明：
- 返回时会对 `api_key` 做脱敏。

## 5. 日志相关

### `GET /api/admin/http-audit-logs?limit=20&offset=0`

用途：查看接口访问审计日志。

说明：
- 记录的是 HTTP 请求，不是 `docker logs`。
- 适合查“某个接口有没有打到服务端”。
- 如果日志时间和北京时间差 8 小时，检查 Docker 容器是否设置了 `TZ=Asia/Shanghai`。

### `POST /api/admin/http-audit-logs/clear`

用途：清空审计日志。

### `GET /api/admin/reply-pool-audit-logs?limit=50&offset=0`

用途：查看**回复池相关**专用日志（盯号 / 同步未读 / 回复检测 / 跟发）。

可选参数：
- `action`：如 `monitor_list`、`account_inbox`、`conversation_read_batch`、`task_submit`
- `account_id`：按发送账号过滤

说明：
- 比通用 HTTP 审计更细：会记下 `unread_conversations`（昵称+预览）以及 `has_reply` 检测结果。
- 同时落盘：`runtime/logs/reply-pool-audit.log`（按天轮转）。

### `POST /api/admin/reply-pool-audit-logs/clear`

用途：清空回复池专用审计日志（Redis 队列；文件需自行清理或等轮转）。

## 6. 常见对应关系

- “本地-查看任务” -> `GET /api/v1/douyin/private-message/tasks`
- “本地-提交任务” -> `POST /api/v1/douyin/private-message/tasks`
- “服务器-提交任务” -> `POST /api/v1/douyin/private-message/tasks`
- “服务器-查看任务” -> `GET /api/v1/douyin/private-message/tasks/{task_id}`
- “服务器-key” -> `POST /api/v1/model/config/save`
- “服务器-查key” -> `GET /api/v1/model/configs`
- “服务器-消息列表” -> `GET /api/v1/douyin/private-message/tasks?limit=20`
- “服务器-清除任务队列” -> `POST /api/v1/douyin/private-message/tasks/clear`
- “服务器-查看任务队列” -> `GET /api/v1/douyin/private-message/tasks?limit=20`
- “服务器-指定任务日志” -> `GET /api/v1/douyin/private-message/tasks/{task_id}`
- “服务器-日志” -> `GET /api/admin/http-audit-logs?limit=20&offset=0`
- “服务器-回复池日志” -> `GET /api/admin/reply-pool-audit-logs?limit=50&offset=0`

## 7. 任务结果里常看字段

- `status`
- `queue_status`
- `error`
- `error_code`
- `failure_code`
- `failure_type`
- `failure_stage`
- `failure_reason`
- `failure_summary`
- `failure_screenshot_url`
- `failure_screenshot_exists`

## 8. 备注

- 如果任务一直是 `pending / queued`，说明还在排队。
- 如果长期停在 `pending / queued`，优先检查 worker 容器是否启动。
- 只有进入失败分支后，才会有失败原因和截图信息。
- 清队列不生效时，先确认是否打到了同一套服务和同一份 Redis。
- 局域网访问失败时，先确认 Web 不是以 `--host 127.0.0.1` 启动，而是以 `--host 0.0.0.0` 启动。
- 上游联调、重试/死信、鉴权和账号限流设计见 `docs/私信任务联调与生产化要点.md`。
- 详细排查见 `docs/运行维护与排查.md`。
