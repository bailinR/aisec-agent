# 运行维护与排查

## 2026-07-16 当前结论

当前服务的正确运行形态是：

```text
外部请求 -> Nginx 8091 -> Web API 容器 127.0.0.1:7860 -> Redis
                                                   |
                                                   +-> worker 容器消费任务队列并执行 Playwright
```

重要结论：

1. Web API 容器只负责接收请求、写入 Redis、查询任务状态。
2. 私信任务要自动执行，必须启动 worker 容器。
3. 任务一直停在 `pending / queued`，通常不是浏览器失败，而是 worker 没消费。
4. 失败截图只有任务真正执行并进入失败分支后才会出现。
5. Docker 容器需要设置 `TZ=Asia/Shanghai`，否则日志时间会显示 UTC。
6. `REDIS_URL` 必须带真实密码和真实 DB，否则会连错 Redis 或报 Redis 认证错误。

## 1. 服务角色

### Web API 容器

容器名：

```text
aisec-agent-api
```

作用：

- 提供健康检查接口
- 提交私信任务
- 查询任务状态
- 清空任务队列
- 查看 HTTP 审计日志
- 暴露失败截图 URL

### worker 容器

容器名：

```text
aisec-agent-dm-worker
```

作用：

- 消费 Redis 自动队列
- 生成私信内容
- 启动 Playwright 浏览器
- 执行私信预填或发送
- 写回成功、失败、截图、失败原因

如果没有 worker，任务会停留在 `pending / queued`。

## 2. 任务状态判断

### `pending / queued`

含义：

- 任务已经提交成功。
- 任务在 Redis 队列里。
- 还没有被 worker 拉走执行。

处理：

```bash
docker ps
docker logs --tail=50 aisec-agent-dm-worker
```

如果没有 worker 容器，需要启动 worker。

### `running / processing`

含义：

- worker 已经取到任务。
- 正在生成私信或操作浏览器。

处理：

```bash
docker logs --tail=100 aisec-agent-dm-worker
```

### `failed`

含义：

- 任务执行失败。
- 查询任务详情时应重点看失败字段。

常看字段：

- `error`
- `error_code`
- `failure_code`
- `failure_stage`
- `failure_summary`
- `failure_screenshot_url`
- `failure_screenshot_exists`

### `manual_required`

含义：

- 自动化无法继续，需要人工处理。
- 常见原因包括登录态失效、二次验证、账号风控、页面结构变化。

### `dead_letter`

含义：

- 最终失败，进入死信队列。
- 通常表示不可重试或重试后仍失败。

## 3. 失败截图

截图只有在任务实际执行并失败时才会生成。

如果任务仍是 `pending / queued`：

- `failure_screenshot_url` 为空是正常的。
- `failure_screenshot_exists` 为 `false` 是正常的。

截图访问形式：

```text
http://8.217.122.152:8091/api/v1/douyin/private-message/artifacts/<文件名>
```

截图文件保存位置：

```text
/www/wwwroot/aisec-agent-api/content/douyin_dm_artifacts
```

## 4. Redis 相关

Docker 启动时必须设置：

```bash
-e REDIS_URL='redis://:你的Redis密码@127.0.0.1:6379/11'
```

注意：

- 密码必须是真实密码。
- DB 必须和实际任务所在 DB 一致。
- 如果清空队列后仍能查到任务，优先怀疑连的不是同一个 Redis 或同一个 DB。

清空任务队列接口：

```http
POST http://8.217.122.152:8091/api/v1/douyin/private-message/tasks/clear
```

成功清空时，日志里会看到类似：

```text
task_count: 4
deleted_keys: 6
cleared: true
```

## 5. 日志类型

### Docker 日志

用途：

- 看容器是否启动
- 看请求是否进服务
- 看 worker 是否消费任务

命令：

```bash
docker logs --tail=100 aisec-agent-api
docker logs --tail=100 aisec-agent-dm-worker
```

如果使用 `docker logs -f`，命令会一直等待新日志，不是卡死。

### HTTP 审计日志

接口：

```http
GET http://8.217.122.152:8091/api/admin/http-audit-logs?limit=20&offset=0
```

用途：

- 看某个 HTTP API 有没有打到服务端。
- 它不是浏览器执行日志，也不是 Docker 日志。

清空接口：

```http
POST http://8.217.122.152:8091/api/admin/http-audit-logs/clear
```

## 6. 时区问题

如果日志显示 `2026-07-15 10:40`，但实际北京时间是 `18:40`，说明容器使用了 UTC。

启动容器时需要加：

```bash
-e TZ=Asia/Shanghai
-v /etc/localtime:/etc/localtime:ro
-v /etc/timezone:/etc/timezone:ro
```

验证：

```bash
docker exec aisec-agent-api date
docker logs --tail=20 aisec-agent-api
```

## 7. 常见失败原因

### Redis 报 `Authentication required`

原因：

- Redis 有密码，但应用没带密码。
- 或者 `REDIS_URL` 没传进容器。

处理：

- 重建容器，补上 `REDIS_URL`。
- 不需要因为 Redis 密码改变重新打包代码。

### 缺少模型 Key

表现：

```text
missing config: api_key
```

处理：

```http
POST /api/v1/model/config/save
```

保存模型配置后，需要重新提交任务。旧失败任务不会自动变成功。

### 任务一直 `pending / queued`

原因：

- worker 没启动。
- worker 连错 Redis。
- worker 消费的队列和任务所在队列不一致。

处理：

```bash
docker ps
docker logs --tail=50 aisec-agent-dm-worker
```

### `message send was not confirmed`

含义：

- 系统尝试发送后，没有在限定时间内确认页面出现已发送消息。
- 不能直接判断是按钮没点上、平台拦截，还是页面没有可识别回显。

处理：

- 看任务详情里的失败字段。
- 看失败截图。
- 必要时人工打开页面确认按钮、输入框、风控提示或登录态。

### `playwright_missing`

含义：

- 当前运行环境缺少 Playwright 或浏览器依赖。

当前处理路线：

- 不在老系统上硬装 Python/Playwright。
- 使用 Docker 新环境运行。

## 8. Postman 常用检查顺序

1. 健康检查：

```http
GET http://8.217.122.152:8091/api/health
```

2. 查看任务队列：

```http
GET http://8.217.122.152:8091/api/v1/douyin/private-message/tasks?limit=20
```

3. 查看指定任务：

```http
GET http://8.217.122.152:8091/api/v1/douyin/private-message/tasks/{task_id}
```

4. 查看 HTTP 审计日志：

```http
GET http://8.217.122.152:8091/api/admin/http-audit-logs?limit=20&offset=0
```

5. 清空任务队列：

```http
POST http://8.217.122.152:8091/api/v1/douyin/private-message/tasks/clear
```
