# 私信回复检测 · 数据中台（comment-kit）开发文档

**版本**：1.0  
**日期**：2026-08-20  
**协作方**：私信系统（aisec-agent）  
**副本位置**：本文件在 aisec-agent 仓库留存，便于联调；正式开发以 comment-kit 侧文档为准时可同步拷贝。

## 1. 职责

- 决定**哪些**已发送线索需要判断回复、**何时**调用  
- 组装参数调用私信系统检测 API  
- 根据返回写 `replied` / `reply_content` / `pm_reply_events`  

私信系统只负责检测并返回结果，不写中台库。

## 2. 调用契约

基址：`private_message_provider.send_base_url`

### 主接口

`POST /api/v1/douyin/private-message/conversations/read`

必填要点：

- `expected_outgoing` ← `message_content`
- `target_profile_url` 或 `sec_uid`
- `account_cookie` 或 `account_key`

### 可选

`GET /api/v1/douyin/private-message/tasks/{provider_task_id}/replies`

### 消费规则

| 返回 | 动作 |
|---|---|
| `has_reply=true` | `send_status=replied`，写回复文案与事件 |
| 无回复且 `outgoing_found=true` | 保持 `sent` |
| `ok=false` / `outgoing_found=false` | 不标 replied |

完整 JSON 示例见 aisec-agent：`docs/数据中台对接抖音私信.md` §6。

## 3. 中台任务清单（回顾）

1. 打开 `private_message_executor_enabled`  
2. 联调 `PrivateMessageProvider.read_douyin_conversation`  
3. 确认仅扫 `send_status=sent`  
4. UI / events 展示回复内容  
5. 端到端验收  

不要用 conversation-monitor 未读气泡作为线索回复依据。
