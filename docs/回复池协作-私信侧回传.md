## 1. 能力对照

| 中台需求 | 私信侧状态 | 说明 |
|----------|------------|------|
| 3.1 盯号 sync/stop/list | **已有** | 多账号可同时 `alive`；默认 `poll_seconds=8`（≥3） |
| 3.2 会话级未读明细 | **已补齐** | `POST .../accounts/inbox` 返回 `unread_conversations` |
| 3.3 读会话正文 | **已有** | `POST .../conversations/read`；**会消红点** |
| 3.4 跟进发送复用 tasks | **已有** | 无「仅首次 / 拒绝已聊过」限制 |

盯号 watch-only 时，`GET .../conversation-monitors` 每条监控快照也带 `unread_conversations`（轮询刷新，不点进会话）。

**浏览器复用（2026-08-25）**：`POST .../accounts/inbox` 若该账号盯号已 `alive`，在盯号线程上复用已打开的浏览器扫一遍（响应带 `reused_monitor=true`），**不再**停盯号、另开窗、再重启。仅当没有盯号时才临时启动浏览器扫完关闭。


2. 盯号 / inbox 建议 `browser_name=edge`  
3. 再点回复池「同步未读」

## 3. 红点 / 副作用约定

| 接口 | 是否消红点 | 说明 |
|------|------------|------|
| `POST .../accounts/inbox` | **否**（设计目标） | 只扫列表角标 + 行预览，**不点进会话** |
| `GET .../conversation-monitors` | **否** | watch-only 同样禁止点开会话 |
| `POST .../conversations/read` | **是（可能）** | 进入会话后抖音未读角标可能消失；以中台回复池记录为准 |

`clears_unread=false` 表示本接口承诺不主动点进会话清未读。

---

## 4. 字段说明与缺口

| 字段 | 稳定性 | 说明 |
|------|--------|------|
| `peer_nickname` | 高 | 列表行解析 |
| `last_message` | 高 | 列表预览，非全文 |
| `unread_count` | 中高 | 来自角标；红点无数字时记为 1 |
| `peer_sec_uid` / `peer_profile_url` | **尽力** | 列表行有 `/user/...` 链接时才有；常为空 |
| `peer_uid` | 尽力 | 同上 |
| `conversation_id` | 中 | 优先 sec_uid，否则 uid/昵称，供中台去重 |
| `updated_at` | 弱 | 多为「刚刚 / n分钟前」相对文案，非严格 ISO8601 |

**再次发送**：优先用 `peer_profile_url`；若为空，中台需用昵称匹配私信库拿到 `sec_uid`/主页后再调 tasks，或对库内用户再调 `conversations/read` 补身份（会消红点）。

陌生人且无 `sec_uid` 时，inbox 仍可入库「非库内」；跟进发送须先补齐 `target_profile_url`。

## 5. 盯号列表附带明细

```http
GET /api/v1/douyin/private-message/conversation-monitors
```

每条 monitor 含：

- `inbox_unread_count` / `inbox_unread_people`
- `unread_conversations`（与 inbox 同结构，轮询刷新）

推荐：开盯号后中台轮询 monitors 取明细，避免频繁 `inbox` 重复开浏览器。`inbox` 适合按钮刷新 / 未盯号账号一次性快照。

---

## 6. 发送 tasks（跟进复用）

```http
POST /api/v1/douyin/private-message/tasks
```

- **无**「仅允许首次 / 拒绝已聊过」校验。
- 传入运营手输 `message` + `target_profile_url`（或等价主页）+ 账号 Cookie/键即可。
- 限流、失败码、登录失效与首次私信相同。

## 8. 私信侧调用与检测日志

中台联调时可查「谁调了什么、扫到了哪些未读、某条线索有没有回」：

```http
GET /api/admin/reply-pool-audit-logs?limit=50&offset=0
GET /api/admin/reply-pool-audit-logs?action=account_inbox&account_id=acc_1001
POST /api/admin/reply-pool-audit-logs/clear
```

覆盖动作：`monitor_sync` / `monitor_list` / `monitor_start` / `monitor_stop` / `account_inbox` / `conversation_read` / `conversation_read_batch` / `task_submit` / `account_verify`。

每条含 `request`（脱敏）+ `detection`（未读明细或 `has_reply` 结果）。文件：`runtime/logs/reply-pool-audit.log`。
