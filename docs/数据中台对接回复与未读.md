# 数据中台对接：私信回复检测与未读

本文给 **comment-kit（数据中台）** 使用。两条能力都已有 HTTP API，不要混用。

测试地址：`http://127.0.0.1:7860`  
生产替换为 `private_message_provider.send_base_url`。

---

## 总览

| 能力 | 用途 | 接口 |
|---|---|---|
| **线索回复检测** | 某条已发出私信之后，对方有没有回、回了什么 | `POST .../conversations/read` 或 `GET .../tasks/{id}/replies` |
| **账号未读** | 发送账号收件箱未读条数 / 未读会话人数 | **推荐一次性**：`POST .../accounts/inbox`；或长驻盯号 `conversation-monitors` |

未读不能代替「某条线索有没有回复」。

---

## 1. 线索回复检测（已有）

### 1.1 主接口

```http
POST /api/v1/douyin/private-message/conversations/read
Content-Type: application/json
```

必填要点：`expected_outgoing`（发出文案）、`target_profile_url` 或 `sec_uid`、`account_cookie` 或 `account_key`。

成功有回复时 `data.has_reply=true`，`data.latest_peer_reply` 为最新对方回复。

### 1.2 任务复用

```http
GET /api/v1/douyin/private-message/tasks/{provider_task_id}/replies
```

从已提交任务取 Cookie / 主页 / 发出文案，内部复用同一套检测。

中台消费：

| 返回 | 动作 |
|---|---|
| `has_reply=true` | 标 `replied`，写回复内容 |
| 无回复且 `outgoing_found=true` | 保持 `sent` |
| `ok=false` / `outgoing_found=false` | 不标 replied |

细节见 `docs/数据中台对接抖音私信.md` §6。

## 2. 账号未读（已有盯号 + 新增一次性接口）

### 2.1 推荐：一次性收件箱快照（给中台「刷未读」）

```http
POST /api/v1/douyin/private-message/accounts/inbox
Content-Type: application/json
```

兼容路径：`/api/douyin/private-message/accounts/inbox`

请求：

```json
{
  "account_cookie": "sessionid=xxx; sid_guard=xxx",
  "browser_name": "chrome",
  "headless": true
}
```

也可用 `account_key`（需本机已有 Playwright profile）。

响应 `data`：

| 字段 | 说明 |
|---|---|
| `ok` | 是否扫成功 |
| `inbox_unread_count` / `unread_count` | 未读消息数（角标合计） |
| `inbox_unread_people` / `unread_people` | 未读会话人数 |
| `requires_login` | Cookie 是否失效 |
| `failure_code` | 如 `login_required` / `inbox_scan_failed` |
| `message` | 说明 |

PowerShell：

```powershell
$body = @{
  account_cookie = "sessionid=xxx; sid_guard=xxx"
  browser_name = "chrome"
  headless = $true
} | ConvertTo-Json -Compress

Invoke-RestMethod `
  -Uri "http://127.0.0.1:7860/api/v1/douyin/private-message/accounts/inbox" `
  -Method POST `
  -Body $body `
  -ContentType "application/json; charset=utf-8"
```

特点：打开消息面板扫角标后关闭，**不点开会话**（避免清未读），也**不常驻盯号进程**。

### 2.2 长驻盯号（已有，可选）

适合需要持续监控/自动回的场景：

```http
POST /api/v1/douyin/private-message/conversation-monitors/start
GET  /api/v1/douyin/private-message/conversation-monitors
POST /api/v1/douyin/private-message/conversation-monitors/stop
```

`GET` 列表里每个 monitor 含 `inbox_unread_count`、`inbox_unread_people`。  
须先 `start`，否则列表为空。说明见 `docs/douyin_private_message_profile_monitor.md`。

---

## 3. 中台建议

1. **回复检测**：执行器只扫 `send_status=sent`，调 §1。  
2. **账号管理未读列**：定时或点按钮调 `POST .../accounts/inbox`，写回 `dm_unread_count` / `reply_people_count`。  
3. 不要用未读人数推断某条线索已回复。

---

## 4. 与验活接口并列

| 接口 | 用途 |
|---|---|
| `POST .../accounts/verify` | Cookie 活性 + 蓝 V |
| `POST .../accounts/inbox` | 未读条数 / 未读会话人数 |
| `POST .../conversations/read` | 单条私信有无对方回复 |
