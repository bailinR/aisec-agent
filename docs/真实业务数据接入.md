# 真实业务数据接入

日期：2026-07-16

这份文档用于对接真实公司业务资料。当前项目不是只依赖一个数据库表，而是由项目资料、知识库、场景模板、活动配置、模型配置和任务接口共同组成。

## 1. 当前项目资料结构

项目资料主要由 `ProjectMaterialStore` 管理，对应代码在：

```text
aisec_agent/logic/project_materials.py
```

典型项目目录结构：

```text
content/session_rag_projects/{project_id}/
  project.json
  global_prompt.md
  scenes/
  knowledge/
    manifest.json
    document_descriptions.json
    chunks.jsonl
    files/
```

重点文件含义：

- `project.json`：项目基础信息。
- `global_prompt.md`：全局私信生成要求。
- `scenes/`：场景资料和场景提示词。
- `knowledge/document_descriptions.json`：知识库、领域、文档树描述。
- `knowledge/manifest.json`：知识文档索引。
- `knowledge/chunks.jsonl`：检索用文本切片。
- `knowledge/files/`：实际知识文档。

## 2. 需要公司提供的基础资料

- 公司全称、简称、品牌名。
- 所属行业、主营业务、核心产品或服务。
- 官网、公众号、企业微信、微信号、电话、地址。
- 服务区域、营业时间、可承接城市。
- 真实业务负责人、技术对接人、内容审批人。
- 对外口径：公司对客户、合作方、平台审核时统一怎么介绍自己。
- 禁用口径：哪些话不能对外说，哪些承诺不能做。

## 3. 数据库资料

接入数据库时，不只要连接串，还要业务含义映射。

### 连接信息

- 数据库类型：MySQL、PostgreSQL、SQL Server、Elasticsearch、Redis 等。
- host、port、库名、schema。
- 只读账号、密码、白名单要求。
- 测试库和正式库地址。
- 是否允许写回，默认建议只读。

### 表和字段

每张表至少要提供：

- 表名。
- 表中文名。
- 表用途。
- 主键。
- 常用查询条件。
- 和其他表的关联关系。
- 数据更新频率。

每个字段至少要提供：

- 字段英文名。
- 字段中文名。
- 字段类型。
- 字段业务含义。
- 是否敏感。
- 是否允许进入模型上下文。
- 是否允许在私信中展示。
- 示例值，必须脱敏。

### 业务映射

需要明确这些业务对象分别来自哪张表：

- 用户、客户、线索。
- 评论、视频、来源平台。
- 账号、Cookie、登录态。
- 私信任务、任务状态、失败原因。
- 订单、预约、活动、资料包。
- 跟进记录、人工处理记录。

## 4. 知识库资料

当前默认知识库分为：

- 公司私信知识库。
- 招聘知识库。

真实接入时可以按业务调整，但建议保持“知识库 -> 领域 -> 板块 -> 文档”的层级。

每篇知识文档需要这些元信息：

```text
title
knowledge_base
domain
section
category
description
keywords
sender_identity
```

字段含义：

- `title`：文档标题。
- `knowledge_base`：归属知识库。
- `domain`：业务领域，例如公司定位、产品资料、售前资料、合规边界。
- `section`：子板块，例如默认板块、岗位名称、具体产品线。
- `category`：分类，用于检索和管理。
- `description`：什么时候应该读取这份资料。
- `keywords`：命中关键词，建议 5 到 12 个。
- `sender_identity`：建议私信身份，例如品牌客服、健康顾问助理、招聘助理。

建议公司提供的知识库文档：

- 公司定位与业务总览。
- 产品或服务说明。
- 适用人群。
- 价格、报价或预约规则。
- 交付流程、服务流程、售后流程。
- 常见问题 FAQ。
- 成功案例或可公开案例。
- 活动、资料包、优惠或评估入口。
- 合规边界。
- 禁止承诺清单。
- 样例私信话术。

## 5. 场景、话术和 CTA

场景资料决定“怎么说”，知识库决定“说什么事实”。

每个场景建议提供：

- 场景名称。
- 适用平台：抖音、小红书、视频号、Boss 等。
- 触发条件：评论关键词、用户行为、业务类型。
- 对话阶段：首次私信、追问、跟进、转人工。
- 目标：留资、加微信、预约、领资料、初步评估。
- CTA：希望用户下一步做什么。
- 回复长度和语气要求。
- 不能说的话。

CTA 示例：

- 加微信。
- 留电话。
- 点链接。
- 预约咨询。
- 领取资料。
- 回复关键词。
- 补充年龄、症状、预算、岗位意向等信息。

## 6. 合规和权限资料

必须单独整理合规边界，不要混在普通产品介绍里。

需要提供：

- 可说内容。
- 不可说内容。
- 敏感词。
- 禁止承诺。
- 平台规则限制。
- 医疗、金融、招聘、价格、效果等高风险表达边界。
- 需要人工确认后才能回复的内容。
- 谁可以改知识库、谁可以审批上线。

## 7. 交付验收清单

上线前至少准备：

- 10 到 30 条真实用户评论或问题。
- 每条问题期望命中的知识文档。
- 每条问题期望生成的回复方向。
- 不能出现的违规表达。
- 需要查数据库的场景和预期字段。
- 需要人工接管的异常样例。

验收时重点看：

- 是否命中正确业务资料。
- 是否没有跨项目串话。
- 是否没有编造价格、效果、资质、名额。
- 是否给出正确 CTA。
- 是否在信息不足时能谨慎追问。

## 8. 相关接口

常用接口见 `docs/API.md` 和 `docs/常用接口.md`。

资料和知识库相关重点接口：

- `GET /api/project-materials`
- `POST /api/project-materials/save`
- `POST /api/project-documents/import`
- `POST /api/admin/knowledge/upload`
- `POST /api/admin/knowledge/save`
- `POST /api/admin/knowledge/delete`
- `POST /api/admin/knowledge/base/update`
- `POST /api/admin/knowledge/domain/update`

私信生成和任务相关接口：

- `POST /api/v1/private-message/generate`
- `POST /api/v1/douyin/private-message/tasks`
- `GET /api/v1/douyin/private-message/tasks`
- `GET /api/v1/douyin/private-message/tasks/{task_id}`
